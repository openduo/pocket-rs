# Pocket Rust

English · [简体中文](README.zh-CN.md)

A cross-platform Rust implementation of the DuoDuo Pocket room protocol: API v2, Chat voice
messages and Ambient audio coordination. Rust applications use `pocket-core`; other languages
link `libpocket_core` through a versioned C ABI. A native reference client exercises HTTP/WebSocket
transport over the network already available to the process. No Go runtime or embedded Tailscale.

[0.1.1 SDK preview](https://github.com/openduo/pocket-rs/releases/tag/v0.1.1) corrects Ambient
media-v1 downlink: kind bytes apply only to uplink; received Opus packets stay unchanged.

```text
Android / Swift / Linux host
      │ commands, completion generations, explicit effects
      ▼
pocket-core — pairing, API, packet framing, live state, Ambient, retries
      │
      └─ platform: network, microphone/speaker, persistence, credentials, lifecycle
```

The core does not acquire audio devices, render UI or start system services. Its effects preserve
hello-after-first-packet, capture-seat ownership, final microphone restoration, idempotent delivery,
stale-callback rejection and the difference between synthesis completion and actual playback drain.
The reference client uses prepared packet files; it is not a finished smart-speaker application.

## Build and use

```sh
cargo test --workspace --locked
cargo build --workspace --release --locked
target/release/pocket self-test
```

The self-test uses real native HTTP/WebSocket sockets on loopback, with a prepared server. It tests
pairing/authentication, text retry, voice upload, speech framing, attachments and Ambient playback/
interruption. It never opens a microphone, plays sound or contacts a real room.

Install a downloaded Linux bundle with an explicit prefix:

```sh
tar -xzf pocket-rs-0.1.1-aarch64-unknown-linux-gnu.tar.gz
cd pocket-rs-0.1.1-aarch64-unknown-linux-gnu
./install.sh --prefix "$HOME/.local/pocket-rs"
"$HOME/.local/pocket-rs/bin/pocket" self-test
"$HOME/.local/pocket-rs/bin/pocket-c-smoke"
```

The bundle contains the shared/static library, C header/module map, `pkg-config` metadata, CLI,
C/Swift consumers, licenses and documentation. See [installation](docs/install.md) and
[validation status](docs/status.md) for native target evidence and exact limits.

## Rust and C consumers

```rust
use pocket_core::{pairing::PairingLink, api::{Api, Surface}};
fn example() -> pocket_core::Result<()> {
    let link = PairingLink::parse("duoduopocket://pair?host=example.test&code=prepared")?;
    // Redeem the code through the host's transport; store the resulting token privately.
    let api = Api::new(link.endpoint, "prepared-room", "device-token")?;
    let request = api.text("stable-message-id", "Hello", &[], Surface::default(), None)?;
    Ok(())
}
```

For a durable session, create `Session`, dispatch typed `Command`s and execute returned `Effect`s.
Persist admission records before returning `Persisted`; report hardware completion only after audio
has played. Every asynchronous result carries its owning generation. Structured errors are localized
by the application. The library stores no credentials globally and performs no implicit room sends.

The C ABI uses opaque integer handles and length-delimited JSON control messages. Audio input has
a binary entry point. Return each result once to `pocket_result_free`; input is borrowed until return.
See [ABI contract](docs/abi.md), [C consumer](examples/c/consumer.c) and
[Swift consumer](examples/swift/Consumer.swift).

## Migration and compatibility

[Migration plan](docs/migration.md) pins the original iOS and Android source revisions. Committed
[compatibility vectors](tests/fixtures/ios-vectors.json) are generated by executing unmodified iOS
source, with [provenance and hashes](tests/fixtures/ios-provenance.json). Regenerate on macOS:

```sh
python3 scripts/generate-upstream-vectors.py --ios /path/to/pocket-ios --check
```

Android now adopts the shared protocol through JNI for Chat request construction, pairing, voice
framing, live validation, Ambient input/output and retry rules. Existing Android networking, storage,
UI and audio resources stay platform-owned; its application coordination does not dispatch a second
Rust Session. See [Android integration](docs/android.md) for exact evidence and ownership. iOS app
integration remains future work through the tested C module/XCFramework. Android Sight negotiation
and video uplink are implemented and separately checked in Pocket Android; camera ownership stays
in the host. Push remains deferred. See the migration plan for the complete remaining scope;
no parity percentage is claimed.
